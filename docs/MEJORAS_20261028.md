# Mejoras y comprobaciones del 28/10/2026

## Cambios realizados

1. **Identidad del producto.** Las expansiones se limitan a prefijos delimitados y conservan atributos y unidades. `Papel aluminio`, `Salsa de tomate` y `Harina integral` mantienen su significado. El alias genérico de papel higiénico requiere evidencia adicional de marca y presentación. Se actualizaron las expectativas antiguas que exigían perder atributos, sin cambiar cantidades, precios ni firmas de aprendizaje.
2. **Incertidumbre OCR.** Las cantidades anteriores y los precios posteriores conservan su confianza al consumirse. Una fila recuperada desde memoria puede mostrar a la vez `AMBIGUOUS` y `memorizado=true`. Las repeticiones se recorren por índice para tomar su propio precio; nunca se usa el importe del producto siguiente ni del resumen para completar uno ausente.
3. **Importes decimales.** Java usa `BigDecimal` y JavaScript enteros `BigInt` con escala. Ambos suman sin redondear cada producto, aplican `HALF_UP` a subtotal y bonificaciones y calculan después el neto. `0,5 × 2,01` resulta en `1,01`; dos filas iguales suman `2,01`. Siete casos compartidos comprueban ambos lenguajes, incluidos descuentos, negativos, pesos y separadores es-AR. Las exportaciones conservan siete columnas.
4. **Evaluación ampliada.** Se añadieron regresiones textuales ficticias de identidad, pesos y repeticiones, y un generador `--challenge` con 16 tickets: ocho de calibración y ocho reservados, con referencias anteriores al OCR y productos distintos entre particiones.
5. **Presupuesto global de PDF.** El valor predeterminado es 300 segundos por archivo, configurable entre 1 y 3600 con `app.pdf.processing-budget-seconds` o `APP_PDF_PROCESSING_BUDGET_SECONDS`. El renderizador comprueba el plazo por página y el OCR recibe el tiempo restante. El límite es cooperativo; una llamada nativa iniciada puede sobrepasarlo. Al agotarse se devuelve HTTP 408 sin productos parciales y se libera la extracción activa. No se eleva el presupuesto OCR por página.
6. **Logs.** Los registros normales mantienen tiempos, cantidades y estados, sin contenido OCR ni comercio, fecha o importe de compra. Los cuerpos de error OCR no se incorporan a los mensajes del navegador. El diagnóstico detallado requiere debug explícito y permanece fuera de Git.

## Medición con PaddleOCR real

Se congelaron las reglas del parser antes de ejecutar los ocho casos reservados del nuevo banco. Se utilizó un backend aislado, memoria vacía y OCR local temporal; no se copiaron credenciales ni se enviaron datos a Sheets. Una ejecución por caso, con presupuesto de búsqueda de **60 segundos por imagen**. El valor predeterminado del proyecto continúa siendo 90 segundos.

Estos tickets contienen atributos, unidades separadas, cantidades fraccionarias, repeticiones, inclinación, rotación, contraste reducido y desenfoque moderado. Siguen siendo sintéticos: **no demuestran esa precisión en fotos reales**, ni miden marcas o comercios. No se comparan con los resultados históricos de siete fotos, cuyas referencias y dificultades son distintas. Las referencias reservadas ya fueron evaluadas y deben considerarse conocidas para futuras iteraciones; no se ajustaron reglas a sus resultados en esta entrega.
